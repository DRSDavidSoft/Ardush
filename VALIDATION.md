# Integration evidence — 2026-10-29

Source comparison: all of the original DRSDavidSoft/Ardush `29be66c` sketch,
README and MIT license were read. No history was rewritten. The replacement
preserves the nine commands through shared components and small application
callbacks; it does not retain an independently maintained duplicate editor.

| Original behavior | Current implementation / boundary |
| --- | --- |
| Uppercase prompt echo | Display-only shared editor transform, on by default |
| Insert, ←/→, backspace, Ctrl-C | Shared bounded event editor; adds history, Home/End and completion |
| Raw `echo` argument tail | Default preserved; parsed argument mode is compile-selectable |
| `led` toggle | Host callback, optional explicit on/off; unknown when no device is supplied |
| `clear`, `test` ENQ | Interactive output only; plain mode avoids clear escape codes |
| `getcur` | Shared 16-byte bounded decoder, 500 ms fixed deadline, rollover-safe, fragmented input |
| Blocking `keycodes` loop | Event mode; Ctrl-C exits while the application loop keeps running |
| `exit` control bytes with no close | Real closed session; old bytes available with `ARDUSH_LEGACY_EXIT_BYTES=1` |
| Arduino `String` allocations and narration | Fixed storage and contextual results; no heap or executing-command narration |
| Original code | Preserved in original Git commits, with MIT attribution retained |

## Local build measurements

All three complete Arduino sketches compiled and linked. These figures are
link-time resources, not measured physical-board RAM or stack consumption.

| Target/profile | Flash bytes | Static RAM bytes | RAM remaining before stack/runtime |
| --- | ---: | ---: | ---: |
| Uno / ATmega328P, prompt | 9,040 / 32,256 | 1,147 / 2,048 | 901 |
| Mega2560, device view enabled | 21,946 / 253,952 | 2,747 / 8,192 | 5,445 |
| STM32F103C8, device view enabled | 26,104 / 65,536 | 2,224 / 20,480 | 18,256 |

Toolchains: Arduino AVR core 1.8.8 with AVR GCC 7.3.0; STM32 core 3.0.0 with
xPack ARM GCC 14.2.1-1.1. STM32 additionally reserves 1,540 linker bytes in
`._user_heap_stack`; this is separate from `.data + .bss`, and not observed use.
Its `.su` report shows 992 bytes for the view feed frame and 424 for rendering;
these individual frames are not a whole-call-chain stack bound. No physical
stack high-water measurement was made. The Uno deliberately excludes the view.

An ATmega328P program executed in simavr 1.5.8, sending command/key/probe bytes
through the actual 16-bit-int implementation. It exercised Tab completion,
history, LED callbacks, fragmented DSR, overflow rejection, timer rollover,
keycodes cancellation and close. Result: `ARDUSH_AVR_PASS`; **887 bytes** of the
fixture's stack/free-RAM watermark region remained untouched. The fixture has
a sink and simulated LED instead of Arduino interrupts/serial; its watermark
is not the Arduino sketch's measured stack margin.

The standalone MCU component object passes symbol audits for ATmega328P and
Cortex-M3. ARM has no undefined symbols. AVR only references its data/bss startup
markers; no libc, allocation, OS or arithmetic-helper symbols are required by
that audited profile. The complete Arduino binary legitimately includes SDK
serial/GPIO/startup code. Headers alone do not promise that every compiler
configuration will avoid generated runtime calls; audit each selected target.

On Windows x86-64, the C batch executable is **28,160 bytes**; session state is
432 bytes and the optional view instance is 584 bytes. A live, idle stdin host
sample used 4,243,456 working-set bytes and 602,112 private bytes (peak working
set at that observation also 4,243,456). Those are whole-process OS/CRT figures,
not shell storage. The shell itself does not allocate.

## Functional and visual checks

Six native suites pass: application command/editor/probe/batch checks,
device-view tab/edit/cancel/exit checks, Telnet framing/NAWS/dumb-terminal checks,
exact shared-source hashes, and guarded legacy/libc/ASCII configurations. PortableShell's seven suites also pass with
both freestanding and optional libc backends. Software decimal conversion was
checked across all 65,536 AVR unsigned values and the host unsigned maximum.

Device, transport, terminal and inline-edit frames were generated by
`tests/render.cpp`, using the canonical PortableShell C ANSI replay utility.
They contain actual emitted bytes from a simulated LED fixture. One Dark is
the replay background, Agave is installed and selected, and the SVG is rendered
at double resolution then downsampled for antialiasing. All four PNGs were
visually inspected. The ImageMagick MSVG backend omitted open border strokes;
the final images use its working RSVG backend. No generated mockup replaces
terminal output. The native tests independently verify state/action transitions.
